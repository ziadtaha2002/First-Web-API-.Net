04 • Registration: step by step

1

Client sends registration JSON

{
  "userName": "Font",
  "email": "font@example.com",
  "password": "Font123#"
}
2

RegisterDTO receives the data

public class RegisterDTO
{
    public string UserName { get; set; } = string.Empty;
    public string Email { get; set; } = string.Empty;
    public string Password { get; set; } = string.Empty;
}

string.Empty gives a safe initial value. Attributes such as [Required] perform validation.

3

Create the Identity user

ApplicationUser user = new ApplicationUser
{
    UserName = request.UserName,
    Email = request.Email
};
4

Let Identity handle the password

IdentityResult result = await _userManager.CreateAsync(
    user,
    request.Password);

Important: Do not manually set PasswordHash when using this overload. Identity validates the password and hashes it safely.

Successful registration means: the user exists in AspNetUsers, while the original password is not stored.

ApplicationUser.cs

public class ITIContext : IdentityDbContext<ApplicationUser>

Program.cs
builder.Services.AddIdentity<ApplicationUser, IdentityRole>()

These three pieces connect the user model, Identity services, and database tables.

06 • JWT login: step by step

1

Receive LoginDTO

public class LoginDTO
{
    public string UserName { get; set; } = string.Empty;
    public string Password { get; set; } = string.Empty;
}
2

Find the user

ApplicationUser? user =
    await _userManager.FindByNameAsync(loginDto.UserName);

If the user does not exist, return 401 Unauthorized. Use the same message for invalid username and invalid password.

3

Verify the password

bool valid = await _userManager
    .CheckPasswordAsync(user, loginDto.Password);

Identity compares the entered password with the stored hash. Never compare plain text passwords yourself.

4

Create claims

new Claim(ClaimTypes.NameIdentifier, user.Id)
new Claim(ClaimTypes.Name, user.UserName ?? string.Empty)
new Claim(ClaimTypes.Email, user.Email ?? string.Empty)

Claims identify the user. Never place a password or password hash in a claim.

5

Sign and return the token

The server uses the secret key to sign the JWT. The client receives only the token and expiration time.

public class LoginResponseDTO
{
    public string Token { get; set; } = string.Empty;
    public DateTime Expiration { get; set; }
}

07 • JWT settings and validation

"Jwt": {
  "Key": "long-development-secret",
  "Issuer": "WebApi",
  "Audience": "WebApiClient",
  "DurationInMinutes": 60
}
SettingSimple meaning
KeySecret used to sign and verify the token.
IssuerThe application that created the token.
AudienceThe client intended to use the token.
DurationHow long the token remains valid.
Production rule: never commit a real JWT key to GitHub. Use User Secrets, environment variables, or a secret manager.

Middleware order

app.UseAuthentication();
app.UseAuthorization();

Authentication identifies the user first. Authorization checks permissions second.

11 • Mistakes to remember

  • Do not return passwords, password hashes, or complete Identity users.
  • Do not manually compare passwords.
  • Use CreateAsync(user, password) for registration.
  • Keep CreateToken private; it is not an endpoint.
  • Return the token DTO in Data, not null.
  • Place UseAuthentication before UseAuthorization.
  • Do not expose real JWT secrets in source control.
  • Use a generic authentication error message.
